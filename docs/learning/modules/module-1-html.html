Module 1: HTML

Structure, semantics, and how this application uses HTML

What is HTML?

HTML (HyperText Markup Language) is the standard markup language for creating web pages. It describes the structure of a web page using a series of elements.

Key Concept HTML is not a programming language — it's a markup language. It doesn't have logic or variables. It simply describes what content is and how it's structured.

HTML in This Application

This application uses minimal HTML. The index.html file is very simple — it just provides containers for JavaScript to fill with content.

index.html (lines 1-30) <!DOCTYPE html>
<html lang="en">
<head>
<meta charset="UTF-8" />
<meta name="viewport" content="width=device-width, initial-scale=1" />
<!-- ... meta tags ... -->
<title>Something for you</title>
</head>
<body>
<div id="photo-stage"></div>
<div id="app"></div>
<script type="module" src="/src/main.js"></script>
</body>
</html>

HTML Document Structure

Every HTML document has a specific structure:

DOCTYPE Declaration

<!DOCTYPE html>

This tells the browser that this is an HTML5 document. It must be the very first line.

html Element

<html lang="en">...</html>

The root element that contains all other HTML. The lang attribute specifies the language.

head Element

<head>...</head>

Contains meta-information about the document (title, meta tags, styles, scripts that don't render directly).

body Element

<body>...</body>

Contains the visible content of the page.

index.html (lines 1-30) This application follows this exact structure. The head contains meta tags, and the body contains the containers and the script tag.

Elements and Tags

An HTML element is defined by a start tag, content, and an end tag:

<tagname>Content goes here</tagname>

Some elements are self-closing (void elements):

<img src="image.jpg" />
<br />
<input type="text" />
In This Application The HTML uses mostly container elements (div) that JavaScript fills with content. The actual content (questions, buttons, text) is generated by JavaScript, not written in HTML.

Attributes

Attributes provide additional information about elements:

<tagname attribute="value">Content</tagname>

Common Attributes

  • id — Unique identifier for an element
  • class — One or more class names for styling
  • src — Source URL for images, scripts, etc.
  • href — URL for links
  • alt — Alternative text for images
  • data-* — Custom data attributes
index.html (lines 24-25) <div id="photo-stage" class="photo-stage" aria-hidden="true"></div>
<div id="app" class="app" role="main"></div>

This application uses:

  • id — To select elements with JavaScript
  • class — For CSS styling
  • aria-hidden — For accessibility (hides decorative elements from screen readers)
  • role — For accessibility (semantic role)

Semantic HTML

Semantic HTML uses elements that clearly describe their meaning:

Semantic Elements

  • <header> — Introductory content
  • <nav> — Navigation links
  • <main> — Main content
  • <section> — Thematic grouping
  • <article> — Self-contained content
  • <aside> — Content aside from main content
  • <footer> — Footer information
src/main.js (lines 120-123) section.setAttribute("aria-label", "Introduction");

While the static HTML is minimal, the JavaScript-generated HTML uses semantic elements. For example, each screen is wrapped in a <section> element with an ARIA label for accessibility.

Why Semantic HTML Matters Semantic HTML improves accessibility (screen readers understand the structure), SEO (search engines understand the content), and maintainability (code is easier to understand).

Common HTML Elements

div

A generic container for content. It has no semantic meaning.

<div class="container">...</div>
index.html (lines 24-25) The application uses div elements as containers for the photo stage and the main app content.

section

A thematic grouping of content, typically with a heading.

<section>
  <h2>Section Title</h2>
  <p>Section content</p>
</section>
src/main.js (lines 120-137) const section = document.createElement("section");
section.className = "screen screen--landing";

button

A clickable button.

<button type="button">Click me</button>
src/main.js (line 129) <button type="button" class="btn btn--primary" data-action="start">

img

An embedded image.

<img src="photo.jpg" alt="Description of the image" />
src/main.js (lines 334-335) <img src="" alt="" loading="lazy" decoding="async" />

p

A paragraph of text.

<p>This is a paragraph.</p>
src/main.js (line 126) <p class="fade-in fade-in--1 text-lead">${escapeHtml(intro.line1)}</p>

h1-h6

Headings, with h1 being the most important and h6 the least.

<h1>Main Heading</h1>
<h2>Subheading</h2>
src/main.js (line 127) <h1 class="fade-in fade-in--2 headline">${escapeHtml(intro.line2)}</h1>

Meta Tags

Meta tags provide metadata about the HTML document. They're placed in the <head> element.

charset

<meta charset="UTF-8" />

Specifies the character encoding. UTF-8 supports all characters and symbols.

viewport

<meta name="viewport" content="width=device-width, initial-scale=1" />

Controls how the page is displayed on mobile devices. This is crucial for responsive design.

description

<meta name="description" content="Page description" />

A short description of the page, used by search engines.

Open Graph (og:*)

<meta property="og:title" content="Title" />
<meta property="og:description" content="Description" />
<meta property="og:image" content="image.jpg" />

Used by social media platforms (Facebook, LinkedIn, etc.) to generate rich link previews.

index.html (lines 5-18) This application uses extensive meta tags for social media sharing. The Open Graph tags ensure that when someone shares the link, it shows a nice preview with an image and description.
Important Social media crawlers read the HTML meta tags, not JavaScript. That's why the meta tags are in index.html even though the application is JavaScript-driven.

Accessibility in HTML

Accessible HTML ensures that everyone, including people with disabilities, can use your website.

ARIA Attributes

ARIA (Accessible Rich Internet Applications) attributes enhance accessibility:

  • aria-label — Provides a label for screen readers
  • aria-hidden="true" — Hides element from screen readers
  • aria-live="polite" — Announces changes to screen readers
  • role — Defines the semantic role of an element
src/main.js (lines 122, 154, 250, 325) section.setAttribute("aria-label", "Introduction");
section.setAttribute("aria-label", `Question ${state.questionIndex + 1} of ${total}`);
section.setAttribute("aria-live", "polite");

alt Text for Images

<img src="photo.jpg" alt="A description of the image" />

The alt attribute provides alternative text for screen readers. It's also displayed if the image fails to load.

src/main.js (lines 372-374) img.alt = gameConfig.recipientName
? `A photo for ${gameConfig.recipientName}`
: "A photo";
This Application's Accessibility The application uses ARIA labels, aria-live for dynamic content, proper alt text, and semantic elements. This makes it accessible to screen reader users.

HTML vs JavaScript Generation

This application uses an interesting approach: the static HTML is minimal, and most content is generated by JavaScript.

Static HTML (index.html)

<div id="photo-stage"></div>
<div id="app"></div>

JavaScript-Generated HTML (main.js)

section.innerHTML = `
  <p class="text-lead">${escapeHtml(intro.line1)}</p>
  <h1 class="headline">${escapeHtml(intro.line2)}</h1>
  <button type="button" data-action="start">${escapeHtml(intro.button)}</button>
`;
Why This Approach? This approach allows for dynamic content (the quiz state changes) and keeps the configuration in config.js rather than hardcoded in HTML. It's a state-driven rendering pattern.
Try It Yourself Open index.html in a browser without running the JavaScript. You'll see just the containers. The actual content only appears when JavaScript runs and fills the containers.

MCQ: Test Your Knowledge

Question 1

What is the purpose of the <!DOCTYPE html> declaration?

  • A) It creates a comment
  • B) It tells the browser this is an HTML5 document
  • C) It links to a stylesheet
  • D) It defines the page title

Answer: B

Explanation: The DOCTYPE declaration tells the browser which version of HTML to use. In HTML5, it's simply <!DOCTYPE html>.

Question 2

Which HTML element is used for the main content of a page?

  • A) <div>
  • B) <section>
  • C) <main>
  • D) <content>

Answer: C

Explanation: <main> is the semantic element for the main content. <div> is generic, and <section> is for thematic groupings.

Question 3

What is the purpose of the alt attribute on images?

  • A) To provide a tooltip
  • B) To style the image
  • C) To provide alternative text for screen readers
  • D) To link the image

Answer: C

Explanation: The alt attribute provides alternative text for screen readers and is displayed if the image fails to load.

Interview Question

Question: Why is semantic HTML important for accessibility?

Answer: Semantic HTML uses elements that clearly describe their meaning (like <nav>, <main>, <article>). Screen readers use these semantic elements to understand the structure of the page and navigate it more effectively. For example, a screen reader user can jump between headings or navigation elements. Without semantic HTML, the page would just be a series of <div> elements, which provides no meaning to assistive technologies.

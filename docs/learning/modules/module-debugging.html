Module 11: Debugging

Systematic debugging with browser DevTools and debugpy

The Debugging Process

Something is broken ↓ Observe symptom ↓ Reproduce reliably ↓ Inspect browser console ↓ Inspect DOM ↓ Inspect CSS ↓ Inspect network ↓ Set breakpoint ↓ Inspect variables ↓ Trace execution ↓ Fix ↓ Retest

Browser DevTools

Every modern browser has DevTools for debugging. Press F12 or right-click and select "Inspect".

Console

Shows errors, warnings, and logs. JavaScript errors appear here in red.

Elements

Shows the DOM tree. You can inspect elements, modify styles, and see computed values.

Sources

Shows source files. Set breakpoints, step through code, inspect variables.

Network

Shows network requests. Check for 404 errors, slow requests, failed assets.

Application

Shows storage (localStorage, cookies), service workers, and more.

Breakpoints

A breakpoint pauses execution at a specific line of code.

Setting Breakpoints

  1. Open Sources panel in DevTools
  2. Click the line number in the source file
  3. A blue marker appears
  4. When execution reaches that line, it pauses

Stepping

  • Step over: Execute current line, move to next
  • Step into: If current line calls a function, go into it
  • Step out: Finish current function, return to caller

Common Bugs in This Application

Photos Not Appearing

Symptom: Photos don't show on the page.

Diagnosis: Check Network tab for 404 errors. Check console for errors.

Fix: Verify image paths in config.js. Ensure images exist in public/assets/photos/.

State Not Updating

Symptom: Clicking buttons doesn't change the screen.

Diagnosis: Set breakpoint in event handler. Check if function is called.

Fix: Check if answersLocked is true. Check if event listener is attached.

Build Fails

Symptom: npm run build fails with errors.

Diagnosis: Read the error message. Check for syntax errors.

Fix: Fix syntax errors. Check import paths. Ensure all files exist.

MCQ: Test Your Knowledge

Question 1

What does a breakpoint do?

  • A) Breaks the code permanently
  • B> Pauses execution at a specific line
  • C) Deletes code
  • D) Optimizes code

Answer: B

Explanation: A breakpoint pauses execution at a specific line of code, allowing you to inspect variables and step through the code.

Question 2

What is the difference between "step over" and "step into"?

  • A) Step over skips lines, step into doesn't
  • B) Step over executes current line, step into goes into called functions
  • C) They are the same
  • D) Step into skips lines, step over doesn't

Answer: B

Explanation: "Step over" executes the current line and moves to the next line in the current function. "Step into" goes into any function called on the current line.

Question 3

Where do JavaScript errors appear in DevTools?

  • A) Elements tab
  • B) Network tab
  • C) Console tab
  • D) Sources tab

Answer: C

Explanation: JavaScript errors appear in the Console tab of DevTools, typically in red text with an error message and stack trace.

Interview Question

Question: How do you debug a memory leak in a JavaScript application?

Answer: Use the Memory panel in Chrome DevTools to take heap snapshots. Compare snapshots to see which objects are being retained unexpectedly. Look for detached DOM nodes that are still referenced by JavaScript. Use the Allocation sampling profiler to track memory allocations over time. Identify event listeners or closures that are holding references to objects that should be garbage collected. Remove unnecessary references and ensure proper cleanup in componentWillUnmount or similar lifecycle hooks.

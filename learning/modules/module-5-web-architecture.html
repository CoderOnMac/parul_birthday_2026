Module 5: Web Architecture

Frontend, backend, static sites, and HTTP

Frontend vs Backend

Frontend is what runs in the browser — HTML, CSS, JavaScript. Backend is what runs on the server — databases, APIs, authentication.

This Application is Frontend-Only This application has no backend. All logic runs in the browser. There's no server processing, no database, no API calls. It's a pure static site.

Static vs Dynamic Sites

Static sites serve pre-built files. Dynamic sites generate files on the fly.

Static Site (This Application) ↓ Pre-built HTML/CSS/JS files ↓ Served as-is ↓ Fast, simple, secure Dynamic Site ↓ Server processes request ↓ Generates HTML ↓ Serves generated HTML ↓ Flexible, complex

HTTP and HTTPS

HTTP (Hypertext Transfer Protocol) is the protocol for transferring data on the web. HTTPS is the secure version with encryption.

GitHub Pages Uses HTTPS This application is served over HTTPS by default on GitHub Pages. This ensures secure communication between the browser and the server.

Client vs Server

Client is the browser (Chrome, Firefox, Safari). Server is the computer that hosts the website.

Client (Browser) ↓ Sends HTTP request ↓ Server (GitHub Pages) ↓ Sends HTTP response ↓ Client renders response

Why This Application Doesn't Need a Backend

  • No user authentication needed
  • No data persistence needed (state is in-memory only)
  • No dynamic content generation needed
  • No API calls needed
  • All logic can run in the browser
Benefits of No Backend Simpler, faster, more secure, cheaper to host, easier to deploy. Static sites are ideal for content that doesn't change frequently.

CDN (Content Delivery Network)

A CDN is a network of servers that deliver content to users based on their geographic location.

GitHub Pages Uses a CDN GitHub Pages is backed by a CDN, which means your application is served from servers close to users around the world, making it fast.

MCQ: Test Your Knowledge

Question 1

What is the main difference between a static site and a dynamic site?

  • A) Static sites use HTML, dynamic sites don't
  • B) Static sites serve pre-built files, dynamic sites generate files on the fly
  • C) Static sites are slower
  • D) Dynamic sites are simpler

Answer: B

Explanation: Static sites serve pre-built files that don't change. Dynamic sites generate files on the fly based on requests, often using a backend.

Question 2

What does HTTPS provide that HTTP doesn't?

  • A) Faster loading
  • B) Better design
  • C) Encryption and security
  • D) More features

Answer: C

Explanation: HTTPS encrypts the communication between the browser and server, making it secure. HTTP sends data in plain text.

Question 3

Why doesn't this application need a backend?

  • A) It's too simple
  • B) All logic can run in the browser
  • C) Backend is expensive
  • D) It uses a CDN instead

Answer: B

Explanation: This application doesn't need authentication, data persistence, or dynamic content generation. All logic can run in the browser, making a backend unnecessary.

Interview Question

Question: When would you choose a static site over a dynamic site?

Answer: Choose a static site when: (1) Content doesn't change frequently, (2) No user authentication or personalization is needed, (3) No server-side processing is required, (4) You want maximum performance and security, (5) You want simple deployment and low hosting costs. Dynamic sites are better when you need user accounts, real-time data, database operations, or server-side processing.

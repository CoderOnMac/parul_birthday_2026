Module 10: Docker

Containers, images, and local development environments

What is Docker?

Docker is a platform for developing, shipping, and running applications in containers. Containers are lightweight, standalone packages that include everything needed to run an application.

Docker is Local-Only for This Project The Docker setup in this project is for local development and learning only. It is NOT part of the production deployment. Production uses GitHub Pages directly.

Image vs Container

Image is a read-only template for creating containers. Container is a running instance of an image.

Image (Template) ↓ docker run ↓ Container (Running Instance)

Dockerfile

A Dockerfile is a script that defines how to build a Docker image.

FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
EXPOSE 5173
CMD ["npm", "run", "dev"]
Dockerfile.local This project uses Dockerfile.local (not Dockerfile) to make it clear it's for local development only.

Dockerfile Instructions

FROM

FROM node:20-alpine

Specifies the base image. This uses Node.js 20 on Alpine Linux (small image).

WORKDIR

WORKDIR /app

Sets the working directory for subsequent instructions.

COPY

COPY package*.json ./
COPY . .

Copies files from the host to the container.

RUN

RUN npm ci

Executes a command during the build process.

EXPOSE

EXPOSE 5173

Documents which port the container listens on.

CMD

CMD ["npm", "run", "dev"]

Specifies the command to run when the container starts.

Docker Compose

Docker Compose is a tool for defining and running multi-container applications.

version: '3'
services:
  app:
    build:
      context: .
      dockerfile: Dockerfile.local
    ports:
      - "5173:5173"
    volumes:
      - .:/app
      - /app/node_modules
docker-compose.local.yml This project uses docker-compose.local.yml for local development. It includes volume mounting for hot reload.

Building and Running

Build Image

docker build -f Dockerfile.local -t parul-birthday-local .

Run Container

docker run -p 5173:5173 parul-birthday-local

Use Docker Compose

docker-compose -f docker-compose.local.yml up

Why Docker for Local Development?

  • Reproducible environment (same as production)
  • Isolated dependencies (no conflicts with system)
  • Easy to share with team members
  • Learning Docker skills

MCQ: Test Your Knowledge

Question 1

What is the difference between a Docker image and a container?

  • A) Image is running, container is not
  • B) Image is a template, container is a running instance
  • C) They are the same thing
  • D) Container is a template, image is running

Answer: B

Explanation: A Docker image is a read-only template for creating containers. A container is a running instance of an image. You can create multiple containers from the same image.

Question 2

What does the FROM instruction do in a Dockerfile?

  • A) Copies files
  • B> Specifies the base image
  • C> Runs a command
  • D> Exposes a port

Answer: B

Explanation: The FROM instruction specifies the base image to build from. All subsequent instructions are applied to this base image.

Question 3

What is Docker Compose used for?

  • A) Writing compose music
  • B> Defining and running multi-container applications
  • C> Building images
  • D) Managing databases

Answer: B

Explanation: Docker Compose is a tool for defining and running multi-container Docker applications. It uses YAML files to configure services, networks, and volumes.

Interview Question

Question: What is the difference between COPY and ADD in a Dockerfile?

Answer: COPY copies files from the host to the container. ADD does the same but also has additional features: it can extract tar files automatically, and it can fetch files from URLs. Best practice is to use COPY unless you specifically need the extra features of ADD, as COPY is more explicit and predictable.

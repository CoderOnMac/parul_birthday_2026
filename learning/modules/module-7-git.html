Module 7: Git

Version control, commits, branches, and collaboration

What is Git?

Git is a distributed version control system. It tracks changes to files over time, allowing you to revert to previous versions and collaborate with others.

Git vs GitHub Git is the version control system (the tool). GitHub is a hosting service for Git repositories (the platform). You can use Git without GitHub, but GitHub needs Git.

The Git Workflow

Working Directory ↓ (git add) Staging Area ↓ (git commit) Commit ↓ (git push) Remote Repository

Basic Git Commands

git status

git status

Shows the current state of your working directory.

git add

git add file.js
git add .

Stages changes for commit. The dot adds all changes.

git commit

git commit -m "Your message"

Creates a commit with a message describing the changes.

git push

git push

Uploads commits to the remote repository.

git pull

git pull

Downloads changes from the remote repository and merges them.

Branches

Branches allow you to work on different features in parallel.

git branch feature/new-photos
git switch feature/new-photos
This Application Uses main Branch This application uses the main branch for production. You could create branches for experiments (like adding new photos) before merging to main.

.gitignore

.gitignore specifies files that Git should ignore.

.gitignore node_modules/
dist/
.DS_Store
Why Ignore These? node_modules/ can be regenerated with npm install. dist/ is generated by the build. There's no need to commit these.

Git History

git log

Shows the commit history.

git log --oneline

Shows a condensed history.

MCQ: Test Your Knowledge

Question 1

What is the difference between Git and GitHub?

  • A) Git is a website, GitHub is a tool
  • B) Git is a version control system, GitHub is a hosting service
  • C) They are the same thing
  • D) GitHub is a paid service

Answer: B

Explanation: Git is the version control system (the software). GitHub is a web-based hosting service for Git repositories. You can use Git locally without GitHub.

Question 2

What does git add do?

  • A) Creates a new file
  • B> Stages changes for commit
  • C) Pushes to remote
  • D) Deletes files

Answer: B

Explanation: git add moves changes from the working directory to the staging area, preparing them for the next commit.

Question 3

What is the purpose of .gitignore?

  • A) To ignore Git commands
  • B> To specify files Git should not track
  • C) To hide files from the user
  • D) To encrypt files

Answer: B

Explanation: .gitignore specifies files and directories that Git should ignore and not track, such as node_modules, build outputs, and OS files.

Interview Question

Question: What is the difference between git merge and git rebase?

Answer: git merge creates a new merge commit that combines the histories of two branches, preserving the complete history. git rebase rewrites history by moving commits from one branch onto another, creating a linear history. Merge is safer and preserves history, while rebase creates a cleaner history but can be dangerous if used on shared branches. Best practice: use rebase for local cleanup, merge for integrating shared branches.
